> 使用方式:把下方 ```` ```prompt ```` 代码块**原样**交给任意 LLM/工程师,
> 填入目标语言与运行环境后执行。需求唯一来源是
> [building-block.md](./building-block.md),无须依赖本仓库源码/Go 变量名。
> "构建即正确"由 §7 验证矩阵把关;凡与本文档冲突的实现均为缺陷。

````prompt
你是一名高级软件工程师。请你用 **{TARGET_LANGUAGE}**、{TARGET_RUNTIME/框架} 重新实现下述
标准构建块:**内存消息总线(MQTT-like,HTTP 发布 + SSE 订阅推送)**。

需求与验收请以用户提供的 `building-block.md` 为**唯一契约**,本提示词只补充实现与验证约束。
不要照抄任何 Go 代码;用目标语言的习惯用法、线程模型与测试框架表达相同语义。

## 一、交付物
1. 库/服务源代码(包或模块,结构自拟,接口以契约为准)。
2. 单元测试 + 集成/契约测试(可运行、有断言)。
3. 运行与测试命令(及如何跑"数据竞争检测",见 §6)。
4. 一份 README:启动方式、API 一览、与契约的差异说明(如有)。

## 二、必须满足的语义(逐条对照 building-block.md §3)
1. 主题过滤:`#`(多级,须末位)/ `+`(单级)匹配矩阵、发布主题禁通配符。
2. QoS0 / QoS1(at-least-once):QoS1 入 in-flight 窗口,SSE 事件带 `id`,
   订阅方 ACK 后出窗,超重投间隔未 ACK 重复推送;实际投递 qos=min(发布,订阅)。
3. **批量 ACK**:ack id=N 视同 id≤N 全部收到,一次出窗。
4. **in-flight 环形窗口**(重点):
   - 固定容量数组 + 头/尾指针,队列内消息 id 单调递增;
   - 满则拒绝新 QoS1(不投递、不覆盖,记日志);
   - ack 在窗口内→移前缀;低于首条或高于末条→no-op(幂等);
   - reset 清空;头推进后 tail 环绕仍保持逻辑顺序。
5. 保留消息(retain)存取/清除/在线补发。
6. 遗嘱(will):异常断流+宽限期超时代发;正常关闭不触发;clean_start 语义。
7. 会话:子树;`clean_start=false`+同 client_id→resumed 恢复订阅表;
   同一会话仅一条流,重复打开顶掉旧流;只投递在线会话。
8. SSE 心跳 `: ping`,写失败判定离线。

## 三、对内有线契约(必须逐字对齐)
- 路由与错误码:见 building-block.md §4(400/404/409/413/429;`{"error":...}`)。
- SSE 事件 4 行块格式(`id:`/`event: message`/`data:`/空行)与心跳行。
- 请求体上限 1024B;参数非法一律 400。
- 消息 id 为**全实例单调递增**。

## 四、并发与生命周期约束(实现必须遵守)
- 单把互斥同步全部共享状态;持锁期间**禁止**阻塞收发/网络 I/O/sleep;
  所有向推送流的写入必须**非阻塞**(缓冲满即丢)。
- 明确三个活动线程/任务:重投循环、遗嘱定时器回调、每流一条读循环(网络写在锁外)。
- 优雅关闭幂等:先停重投→等待退出→持锁销毁会话并关流。
- 顶替保护:旧流的清理仅在"仍等于当前流"时生效,不得误拆新流。
- 不产生 goroutine/线程/定时器泄漏。

## 五、鉴权扩展位(可选,但接口留位)
提供可插拔授权点:身份由宿主中间件注入;发布/订阅前调 Authorizer;
未配置时全放行;提供与缺省一致的 allow/deny 规则与 default-deny 语义
(未注入→401,已注入被拒→403)。不想做可在 README 注明并保持接口位。

## 六、验证方式
- 先自测再交付:你的实现**必须**通过你自己编写的、下述 §7 全部用例后才可结束。
- 数据竞争检测:若目标语言有 race detector(Go `-race`、Rust TSAN、Java JFR/TSAN、
  C++ TSAN 等)就开启并跑全部测试;没有则说明你的串行化论证(为什么无竞态)。
- 可用你语言中最快的 HTTP 测试方式(内嵌 server / 进程内直调)。

## 七、验证矩阵(测试用例清单,缺一不可)

### A. 主题匹配
- `#` 匹配 `a`、`a/b`、`a/b/c`
- `a/+` 匹配 `a/b`,不匹配 `a`、`a/b/c`
- `a/#` 匹配 `a`、`a/b`、`a/b/c`
- `+/+` 匹配 `a/b`,不匹配 `a`
- `a/b` 精确匹配 `a/b`,不匹配 `a/b/c`

### B. 参数校验(均应拒绝)
- 空 filter;`a//b`(空层级);`a/#/b`(# 非末位);`a#`(# 混级);`a+/b`(+ 混级);`$share/...`
- 发布:空 topic;topic 含 `+` 或 `#`;qos=2

### C. in-flight 环形队列
- push 到满;满后再 push → 拒绝且 len/内容不变
- 窗口 `[5,8,10,12]`:ack 8 → 移除 5、8,剩 `[10,12]`
- ack 10(恰首条)→ 移除 10
- ack 低于首条(如 3)→ 0 移除,不变
- ack 高于末条(如 99)→ 0 移除,不变(视同陈旧;不批量清空)
- 空队列 ack → 不 panic,0 移除
- 环绕:push 1,2,3 → ackUpTo(2)→ push 4(尾回绕)→ 顺序 `[3,4]`;ackUpTo(3) → 剩 `[4]`
- reset → 空,再从 0 开始

### D. QoS1 / 批量 ACK
- 发布 QoS1 → 投递;不 ACK → 到达重投间隔后再次投递;ACK → 不再投递
- 同窗多条,ack 最大 id → 该窗全清(不再重投)
- ACK 幂等;非数值 message_id → 400
- 实际投递 qos:发布 1 + 订阅 0 → 收到 qos=0

### E. 保留消息
- publish retain → 新订阅(流在线)立即收到 `retain=true` 补发
- reopen stream 补发匹配保留
- 空 payload retain → 清除该主题保留

### F. 遗嘱
- 异常断流 + 超宽限 → 订阅方收到遗嘱;正常 CLOSE/DELETE session → 不收
- clean_start=false 超时只发遗嘱不销毁;clean_start=true 超时销毁

### G. 会话/流
- clean_start=false 同 client_id → resumed=true 且订阅表保留;true → 清空
- 打开两条流 → 后一条生效,前一条收到关闭;Publish 只达新流
- DELETE stream → 会话保留、订阅表保留、不再在线
- 只投在线会话:离线时 Publish,delivered=0

### H. 契约与错误码
- 逐条列出 400/404/409/413/429 触发用例并断言状态码
- SSE 格式可被标准 SSE 客户端(如 EventSource)消费才对

### I. 并发/健壮性
- race 检测下全绿;并发发布+ACK+断流混合压力不挂、不竞态
- Close 幂等、无泄漏;推送流 handler panic 不拖垮进程且会话被回收
````
